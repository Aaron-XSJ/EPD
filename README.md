# EPD：会播放音乐的 CD 冰箱贴

> **EPD = Electronic Paper Display（电子墨水屏）**。最终形态是一枚贴在冰箱上的音乐冰箱贴：墨水屏常驻显示 CD 封面，像一张怀旧 CD 盒；按键切歌，小喇叭出声。
>
> 本仓库是它的**播放链路验证工程**：STM32F103ZE + TF 卡 + VS1003，已跑通流畅 MP3 播放。墨水屏已在独立工程中点亮，尚未与本工程合板；封面、电池、外壳仍待实现。

---

## 双缓冲喂数据：播放为什么不卡顿

难点不在解码，而在**喂数据**。VS1003 片内 FIFO 很浅，`DREQ` 拉低表示「FIFO 满、正在解码」，此时不能再送；而 STM32F103 是裸机、无操作系统、无 DMA 参与，从 TF 卡 `f_read()` 读 512 字节的耗时又随卡速波动。若用单缓冲，读卡这段时间没有数据可送，FIFO 一空就是听得见的断续。

本工程用**两块 512 字节静态缓冲 + DREQ 流控**，把「读卡」和「发送」在时间上错开：

```mermaid
flowchart LR
    SD["TF 卡 / SDIO 4-bit"] -->|"f_read 512B"| BUF["乒乓缓冲 buf0 / buf1"]
    BUF -->|"SPI1 每次 32B"| VS["VS1003 硬件解码"]
    VS -.->|"DREQ 高:可送 / 低:解码中"| BUF
    VS --> OUT["模拟输出"]
```

| | `DREQ = 0`（FIFO 满，芯片在解码） | `DREQ = 1`（可接收数据） |
| --- | --- | --- |
| 主循环在做什么 | **趁这段时间阻塞读卡**，填满另一块缓冲 | 把当前缓冲以 32 字节为单元送进 SDI |
| 为什么划算 | CPU 本来就在等芯片，读卡抖动不会立刻造成断流 | 每次发送前后重查 DREQ，不会撑爆 FIFO |

`VS_PlayFile()` 用 `send_buf` / `fill_buf` 两个指针指向两块缓冲，缓冲发空时**只交换指针，不做内存拷贝**：

```c
预读第 1 块 → send_buf
while (1) {
    if (DREQ == 0) {
        if (send_buf 空 && 未到文件尾)
            f_read(fill_buf, 512);        /* 读卡藏在解码时间里 */
        delay_us(20); continue;
    }
    if (send_buf 有数据) SPI 送 ≤ 32 字节;
    else { f_read(fill_buf, 512); 交换 send_buf / fill_buf; }  /* 慢卡兜底补读 */
    if (到文件尾 && send_buf 空) break;
}
VS_EndOfSong();   /* 冲净 FIFO，每曲独立复位，切歌不留尾音 */
```

**关键点**

- **隐藏延迟**：SD 读卡被安排在 DREQ 拉低期间，芯片正在消耗片内数据，读卡慢一点不会立刻断流。
- **零拷贝切换**：预读块变成待发块只需交换两个指针，512 字节量级内完成。
- **不会死锁**：DREQ 低时预读（正常路径）、DREQ 高但缓冲已空时立即补读（兜底路径），慢卡 / 高码率都有路可走；发送按 32 字节分块，贴合 VS10XX 的 DREQ 语义。
- **收尾干净**：曲末按 32 字节分块补 2048（VS1003）/ 2052（VS1053）字节 `0x00` 冲净 SDI FIFO，每曲开头硬复位 + 软复位，解码状态不跨曲继承，切歌没有残留尾音。

| 参数 | 值 |
| --- | --- |
| 缓冲 | `buf0[512]` / `buf1[512]`，静态共 1KB |
| 单次推送 | ≤ 32 字节 |
| 总线 | SDIO 4-bit 读卡（轮询）、SPI1 约 9MHz 送数据 |
| 流控 | `DREQ = PB0`，高可送 / 低解码中 |
| 曲库 | TF 卡根目录、8.3 短名 `.MP3` / `.WAV`、最多 32 首、循环播放 |

> 准确定位：这是**软件乒乓 + 轮询 SPI 的时间重叠**，不是 DMA 并行。好处是不依赖 DMA / 中断、逻辑简单、在 F103 上足够稳；代价是 512B 缓冲在 128kbps 下约覆盖 31ms，320kbps 或很慢的卡余量会变小，可加大缓冲或启用工程里未编译的 DMA 方案（`HARDWARE/VS10XX/vs1003.c`）。

## 硬件连接

| 模块 | 接口 | 引脚 |
| --- | --- | --- |
| TF 卡（microSD） | SDIO 4-bit | PC8~PC12、PD2、PD7 |
| VS1003 数据 SDI | SPI1 | PA5(SCK) / PA6(MISO) / PA7(MOSI) |
| VS1003 控制 SCI | GPIO | PA8(XCS)、PA4(XDCS) |
| 握手 / 复位 | GPIO | PB0(DREQ)、PE11(RST) |
| 按键 | GPIO | PA0(WK_UP 下一曲)、PE4(KEY0 暂停) |
| 指示灯 | GPIO | PB5(LED0)、PE5(LED1) |

> 音频文件在 **TF 卡**上，SPI 连的是 **VS1003 解码芯片**；`HARDWARE/LCD` 是开发板自带的 TFT 模板，与墨水屏无关。

## 快速开始

1. Keil MDK 打开 `USER/EPD.uvprojx`（目标芯片 STM32F103ZE）编译，或直接烧录 `OBJ/EPD.hex`。
2. 自备 MP3/WAV 拷到 TF 卡**根目录**，FAT32 格式，文件名用 8.3 短名、后缀大写（如 `01.MP3`）—— FatFs 配置了 `_USE_LFN = 0` / `_CODE_PAGE = 936`。
3. 插卡、接好 VS1003 模块与耳机 / 音箱，上电即按根目录顺序循环播放。
4. `WK_UP` 切下一曲，`KEY0` 暂停 / 继续。
5. LED0 500ms 闪 = 卡或文件系统异常；300ms 闪 = 根目录无音频文件。
